# SAR 散射点引导目标检测

研究问题：预测散射点的位置，能否通过引导可形变卷积采样，稳定改善 SAR 目标检测？

本仓库于 2026-10-27 建立。目前仅包含实验管理骨架，尚未迁入模型、安装训练环境或运行实验。旧工程保留在上级目录，不能直接把历史指标当作本项目的对照结果。

## 目录

- `configs/`：模型、训练与数据配置。
- `splits/`：固定的数据划分名单及生成规则，不保存图像。
- `scripts/`：数据检查、训练与评估入口，待实现。
- `src/`：模型修改，待选择上游版本后迁入。
- `records/`：精简实验记录与结果表，可提交 Git。
- `EXPERIMENTS.md`：实验协议、对照组和执行顺序。

本地可将数据放在 `data/`，运行输出放在 `runs/`，备份权重放在 `checkpoints/`；这些目录默认被 Git 忽略。

## 开始训练之前

1. 核对 FAIR-CSAR 数据、类别映射、点标注定义及使用许可。
2. 检查原始场景关联和重复数据，生成 train/val/test 名单并记录哈希。
3. 明确 YOLOv8s 上游来源、许可证及具体版本或提交，迁入必要代码。
4. 在远程 GPU 环境验证 PyTorch、torchvision 和 DCN 算子兼容性，记录依赖版本。
5. 跑通少量数据的训练、验证、权重保存和恢复流程，再提交可复现的代码与配置。
6. 按 `EXPERIMENTS.md` 开始完整实验。

当前没有可用的训练命令。不要将模板配置误作已经验证的实验配置。

## 版本和备份

- Git 保存源代码、配置、划分名单、环境说明和精简实验结果。
- 不提交数据集、权重、完整运行输出、访问令牌或 SSH 私钥。
- 每次完整训练使用唯一实验编号，记录干净工作区的 Git commit；有未提交修改时先提交，或另存可恢复的补丁并注明。
- 远程 GPU 服务器只作为执行环境；日志和权重应同步至本地或独立持久存储，并记录路径及 SHA-256。
- Git 尚未配置远程地址。后续可连接私有仓库；远程备份完成前，本地仓库仍然只有一份。
