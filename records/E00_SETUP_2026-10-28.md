## 短训练

```bash
conda activate yolov10
cd /root/sar-scattering-detection
git pull --ff-only
mkdir -p outputs
set -o pipefail
python -u scripts/train_e00.py --mode smoke --name E00_smoke_s0_001 2>&1 | tee outputs/E00_smoke_s0_001.log
```

固定从冻结 train 抽 64 图、val 抽 32 图，抽样种子 20261028；模型随机初始化种子 0，2 epochs、1024、batch 8、workers 4、FP32、无 RAM/磁盘图像缓存。保留缩放和平移，关闭翻转、旋转、HSV、Mosaic/MixUp/CutMix 等混图和额外滤波。没有 test 路径，不评测 test。

短训练 warmup_epochs=0 以便实际检查 SGD 更新，其余配置来自 `configs/e00_yolov8s.json`。短训练没有预训练权重，避免把历史 `.pt` 的来源或内容直接当作正式初始化。FP32 是当前保守流程选择，混合精度策略可在正式对比之前统一验证和确定。

入口在 train loader 完成初始化后检查图片数和目标数与抽样清单完全一致，遇框架丢图/丢目标会停止；保存环境、完整请求参数、框架 args.yaml、实际增强链、源码哈希、CSV、best/last 权重及哈希，结束后重载 best.pt 做一张 val 图推理。已存在的同名运行目录拒绝覆盖，失败后换新编号；保留失败记录。

`PASS` 表示该流程检查完成，不表示模型精度足够，也不表示中断恢复已验证。短训练结果不与正式结果混用。

## 断点恢复小测试

```bash
python -u scripts/train_e00.py --mode resume-smoke --name E00_resume_s0_001 2>&1 | tee outputs/E00_resume_s0_001.log
```

仍用同一组 64/32 图，设置总共 3 epochs。在第 1 轮正常写完 checkpoint 后由回调有意中断，避免进入上游 final_eval 清除 optimizer；启动全新 Python 子进程，执行 `resume=True`，要求 start_epoch=1、optimizer.state 非空、EMA updates>0，继续完成剩余 2 轮并运行原有最终检查。失败的第一阶段不会启动第二阶段。

它验证恢复机制可用，不声称中断前后的随机数/数据加载器状态完全等同于一次不间断运行。完成训练后日志中的 `Optimizer stripped` 是上游行为；不可用第一轮已经结束的 2-epoch 权重冒充可恢复的训练中断点。
